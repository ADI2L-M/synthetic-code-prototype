## Least-effort verification order

1. **Recover prior outputs first.** If `outputs/authentic-functional-filter/summary.json` and the two CSVs still exist in a backup, compare their task counts with the 46 stored prevalence reports. This fills the functional counts and failure-reason gap without rerunning student code. Record file hashes and the run timestamp.
2. **Recover the workbook and mapping in the authorised research environment.** Compare the mapping labels with the retained 46-task index and the existing test plans. A read-only inventory can establish nonblank response counts and duplicates using hashes; it need not execute submissions.
3. **Rerun functional validation only if the original results cannot be recovered.** The project already has `run_authentic_filter()` in `services/authentic/filter.py` and the 46 test plans. It requires the workbook's right-answer columns. The current runner's timed subprocess is not a security sandbox, so use an approved isolated execution environment before running untrusted submissions.
4. **Use the existing detector tools for static checks.** `scripts/validate_detectors.py` and `services/research/prevalence_runner.py` cover detector cases and aggregation. The current static detectors already reproduced 1,292/1,292 retained active-detector case labels; 40 old `redundant_for` cases are outside the active registry. This verifies reproducibility, not label correctness.
5. **Collect non-code evidence separately.** Ethics/data-use authorisation, original task wording, cohort scope, and an independent detector-label review protocol need source documents or researcher records. No test command can establish them.
